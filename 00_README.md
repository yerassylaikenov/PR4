## Как запускать

1. В WSL2 работайте в Linux-ФС, а не в `/mnt/c` (иначе Docker и Go будут очень медленными):
   ```bash
   mkdir -p ~/hlf-pr4-variant1/{prompts,docs/architecture} && cd ~/hlf-pr4-variant1
   # скопируйте 01–04 в prompts/, а architecture_variant1.drawio — в docs/architecture/
   ```
2. Запустите `claude`, переключитесь в plan mode (Shift+Tab) и напишите:
   `Прочитай prompts/01_task1_network_chaincode.md и выполни его полностью. Сначала покажи план.`
3. После каждого задания: пройдите чек-лист «Definition of Done» в конце промпта, сделайте скриншоты из списка, затем `/clear` и следующий промпт. Промпт 1 создаёт `CLAUDE.md` с общими правилами — следующие сессии подхватят его автоматически.
4. Команды с `sudo` Claude Code выполнить не сможет (нет ввода пароля) — он попросит вас выполнить их вручную.

**Порядок строго 1 → 2 → 3 → 4.** Основная сеть живёт от Задания 1 до пункта 3.6 включительно. SmartBFT-стенд (3.7) требует остановки основной сети — промпт 3 сначала заберёт все доказательства и бэкап, а затем спросит ваше подтверждение перед `network.sh down`.

## Что остаётся на вас

Скриншоты (списки есть в каждом промпте), ФИО преподавателя на титульном листе, финальная вычитка, что в отчёт не попали ключи, пароли и сертификаты с приватными ключами.

## Покрытие критериев оценки

| Ограничение из задания | Где закрывается |
|---|---|
| ≤ 50, если сеть или chaincode не запускаются | Промпт 1: деплой, `querycommitted`, ≥ 4 VALID-транзакции с TxID |
| ≤ 70 без доказательства разграничения доступа и исправления уязвимости | Промпт 2: эксплойт на `paymentvuln` → тот же сценарий на `paymentsecure` даёт отказ; тесты Org1 vs Org2 для `privateDetails` |
| ≤ 80 без апгрейда seq 1 → 2 с сохранением состояния | Промпт 3: снимок до и после, чтение объектов v1.0 через v2.0, старая и новая операции |
| Публикация секретов = критическая ошибка | Все промпты: `redact.sh`, `.gitignore`, `scan_secrets.sh` (gitleaks) перед сдачей |
