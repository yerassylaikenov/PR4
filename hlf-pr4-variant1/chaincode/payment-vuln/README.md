# ⚠ paymentvuln — УЧЕБНЫЙ УЯЗВИМЫЙ CHAINCODE (ПР №4, Задание 2.2)

**Не использовать вне лабораторного стенда.**

Копия `chaincode/payment-v1` с **ровно одной** преднамеренной ошибкой бизнес-логики:

> `SubmitPaymentOrder` не проверяет MSP вызывающей стороны (OWASP SC01:2025 Access Control → SC03:2025 Logic Errors).

Submit — авторизация списания банком-отправителем. Без проверки банк-получатель (Org2) может в одиночку провести поручение `CREATED → SUBMITTED → ACCEPTED → SETTLED`.

Нарушаемые инварианты:
- **INV-4** — перевод в SUBMITTED выполняет только банк-отправитель (`senderBankMSP`, роль approver);
- **INV-SoD** — ни одна организация не может единолично провести платёж от создания до исполнения.
